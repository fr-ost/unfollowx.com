# Google Analytics 4 + Google Tag Manager setup

| | |
| --- | --- |
| GA4 measurement ID | **G-DEEP3H3Q83** |
| GTM container ID | **GTM-M4QHPXQV** |
| Integration | Official Google tag snippet (`gtag('js')` + `gtm.js`) rendered into **every page’s `<head>`** with **Google Consent Mode v2** defaults. **GA4 runs inside GTM** (`GA4_DELIVERY = 'gtm'`). |
| Consent UI | `components/Analytics.jsx` (banner + footer “Analytics settings”) |
| Code | `lib/analytics-config.js` (IDs + head snippet), `app/layout.jsx` (renders it), `lib/analytics.js` (consent updates + events), `components/Analytics.jsx`, `components/InstallLink.jsx` |

## How it works

The Google tag is in the server-rendered HTML of every page (so Google’s “Test your website” / tag detection finds it). One inline `<head>` script, generated by `googleTagHeadScript()` in `lib/analytics-config.js`, runs before anything else from Google:

1. `window.dataLayer` + `gtag()` are defined.
2. The stored choice (`localStorage` key `unfollowx-analytics-consent`) and Global Privacy Control are read, then **Consent Mode defaults** are queued **first**:

   | Visitor state | `analytics_storage` | `ad_storage`, `ad_user_data`, `ad_personalization` | GA4 |
   | --- | --- | --- | --- |
   | No choice yet | denied | denied | runs **cookieless** (no `_ga` cookies; Google may receive cookieless pings for modelling) |
   | Accepted | granted | denied | normal measurement with cookies |
   | Declined, or GPC with no choice | denied | denied | **switched off** via `window['ga-disable-G-DEEP3H3Q83'] = true` — sends nothing |

   `gtag('set', 'ads_data_redaction', true)` is also set.
3. `gtag('js', new Date())`.
4. The standard GTM bootstrap event `{ 'gtm.start', event: 'gtm.js' }`, then `gtm.js?id=GTM-M4QHPXQV` is injected as an async script from the same inline script — so the consent defaults are guaranteed to be queued before GTM runs. (Only in `'gtag'` mode would `gtag('config', …)` and `gtag/js?id=G-DEEP3H3Q83` also be added.)

**Accept** → `gtag('consent', 'update', { analytics_storage: 'granted' })`. **Decline** → `ga-disable` on, `consent update` denied, `_ga`/`_ga_*` cookies deleted, custom events stop. Choices are stored in `localStorage`; “Analytics settings” in the footer reopens the banner. Custom events (below) are sent in the “no choice” and “accepted” states, never after Decline or with GPC.

The `<noscript>` GTM iframe is intentionally not used: it would load GTM for visitors whose browser can’t run the consent logic.

> **History:** the first version loaded nothing until the visitor clicked Accept. Google’s tag detection never saw the tag, so on 2026-11-06 the site moved to the standard Consent Mode setup above (owner’s decision). Stricter readings of EU ePrivacy law consider even cookieless pre-consent pings to need consent; revisit with legal advice if you target EU users heavily.

## GA4 runs through GTM (one path only)

`lib/analytics-config.js` → `GA4_DELIVERY = 'gtm'`: the site does **not** load gtag.js. GA4 must be configured in container **GTM-M4QHPXQV**, or GA4 receives no data.

### Set up the container (2 minutes, import file provided)

1. Open [Tag Manager](https://tagmanager.google.com) → container GTM-M4QHPXQV → **Admin → Import container**.
2. Choose `docs/gtm/unfollowx-ga4-container.json` from this repository.
3. Workspace: **Existing** (Default Workspace). Import option: **Merge** → **Rename conflicting tags, triggers and variables**. Confirm.
4. Check the preview, then **Submit → Publish**.
5. If the container already had its own Google tag or GA4 tags for G-DEEP3H3Q83, pause or delete the duplicates so each hit is sent once.

The import adds:

| Item | Configuration |
| --- | --- |
| Tag: Google tag – G-DEEP3H3Q83 | Tag ID `G-DEEP3H3Q83`, trigger **All Pages**, config `allow_google_signals = false`, `allow_ad_personalization_signals = false`. Sends the first `page_view`; SPA page views come from GA4 Enhanced measurement. |
| Tag: GA4 event – UnfollowX site events | Measurement ID `G-DEEP3H3Q83`, event name `{{Event}}`, 18 event parameters mapped to data layer variables |
| Trigger: CE – UnfollowX site events | Custom Event, regex `^(chrome_install_click|cta_click|blog_article_view|feature_page_view|faq_expand|navigation_click|theme_change|outbound_link_click|demo_interaction)$` |
| Variables: DLV – `<param>` | Data Layer Variable v2 for each of `page_location`, `page_path`, `button_location`, `button_text`, `cta_name`, `cta_location`, `article_title`, `article_category`, `article_slug`, `feature_name`, `faq_question`, `navigation_item`, `navigation_location`, `selected_theme`, `link_url`, `link_text`, `interaction_type`, `demo_section` |
| Built-in variable | Event |

The import file was generated from the site’s event list but could not be test-imported from the build environment (Google domains blocked). If GTM rejects it, create the same items by hand from the table above.

Each site event is pushed as `dataLayer.push({ event: '<name>', …params })`, with every other known parameter set to `undefined` so values don’t carry over between events in GTM’s data model.

### Switching back

Set `GA4_DELIVERY = 'gtag'` and remove or pause both imported tags in GTM. The site then loads gtag.js and sends GA4 directly.

## Page views and client-side navigation

- The **first page view** is sent by `config` (gtag mode) or the Google tag (GTM mode).
- **Client-side route changes** (Next.js navigation) are counted by GA4 **Enhanced measurement → Page views → “Page changes based on browser history events”**, on by default for web streams. The app does **not** send its own `page_view` — that would double count.
- If you turn that setting off, set `MANUAL_PAGE_VIEWS = true` in `lib/analytics.js`; the app then sends `page_view` (gtag mode) or a `virtual_page_view` dataLayer event (GTM mode) on every route change, deduplicated per path.

## Events

Lowercase snake_case, consistent parameter names. Each event is pushed once to the dataLayer as `{ event: name, …params }` (GTM mode). In gtag mode it is also sent with `gtag('event', …)`.

| Event | Parameters | Fired when | Where |
| --- | --- | --- | --- |
| `chrome_install_click` | `page_location`, `page_path`, `button_location`, `button_text` | Any click on a Chrome Web Store link. **An outbound install attempt, not a confirmed installation.** | Delegated click handler; every store link is `components/InstallLink.jsx` or has `data-install` + `data-location` |
| `cta_click` | `cta_name`, `cta_location`, `page_path` | Clicks on internal CTA links/buttons with `data-cta` | Delegated |
| `blog_article_view` | `article_title`, `article_category`, `article_slug` | Article page viewed | `TrackEvent` in `app/blog/[slug]/page.jsx` |
| `feature_page_view` | `feature_name`, `page_path` | `/features` (`features_overview`), `/twitter-non-followers-checker` (`non_followers_checker`), `/x-follower-tracker` (`follower_tracker`) | `TrackEvent` |
| `faq_expand` | `faq_question`, `page_path` | A FAQ item is opened (not on close) | `components/FaqAccordion.jsx` |
| `navigation_click` | `navigation_item`, `navigation_location` (`header`, `mobile_menu`, `footer`) | Header, mobile menu and footer navigation links | Delegated (`data-nav`) |
| `theme_change` | `selected_theme` (`light` / `dark`) | Theme toggle | `components/SiteHeader.jsx` |
| `outbound_link_click` | `link_url` (origin + path, no query), `link_text`, `page_path` | External http(s) links other than the store (`mailto:` is never tracked) | Delegated |
| `demo_interaction` | `interaction_type`, `demo_section` | Homepage demo: `view_switch`, `filter_change`, `search`, `select_account`, `select_all`, `whitelist_toggle`, `simulate_scan`, `simulate_unfollow`, `simulate_follow_back`, `reset` — **each type at most once per page view** | `components/ProductDemo.jsx` |

`button_location` values: `hero`, `header_nav`, `mobile_menu`, `how_it_works`, `final_cta`, `footer`, `footer_links`, `features_hero`, `features_cta`, `setup_hero`, `setup_step`, `setup_cta`, `checker_hero`, `checker_cta`, `tracker_hero`, `tracker_cta`, `guides_cta`, `faq_cta`, `blog_inline`, `blog_sidebar`, `blog_footer_cta`, `blog_index_cta`.

### Never sent

X usernames, passwords, account lists, follower data, emails, tokens, anything typed in the demo search box, or query strings of outbound links. `track()` trims every string parameter (100 characters; 300 for URLs).

## Conversion reporting

1. **GA4 Admin → Events** → toggle **Mark as key event** on `chrome_install_click` (appears after the first event is received).
2. **Custom dimensions** (Admin → Custom definitions, event scope): `button_location`, `cta_location`, `article_category`, `feature_name`, `navigation_location`, `interaction_type`.
3. Useful explorations:
   - **CTA engagement:** Free-form, rows `button_location`, metric event count of `chrome_install_click`.
   - **Organic landing pages:** Reports → Engagement → Landing page, filter *Session default channel group = Organic Search*; add key event rate for `chrome_install_click`.
   - **Blog → install journeys:** Path exploration starting at `blog_article_view`, next step `chrome_install_click`; or a Funnel exploration: `blog_article_view` → `chrome_install_click`.
   - **Feature → install journeys:** Funnel: `feature_page_view` → `chrome_install_click`, broken down by `feature_name`.

Always describe `chrome_install_click` as an **install attempt**. Confirmed installs are only visible in the Chrome Web Store developer dashboard.

## Verification

### DebugView

1. Install the **Tag Assistant** browser extension or open [tagassistant.google.com](https://tagassistant.google.com) and connect to `https://www.unfollowx.com`.
2. Accept the analytics banner in the debugged tab.
3. GA4 → Admin → **DebugView**: you should see `page_view`, then events as you click (e.g. `chrome_install_click` with `button_location = hero`).
4. In Tag Assistant, the GTM container should show the `gtm.js` event and any tags you configured.

### Realtime

GA4 → Reports → **Realtime**: after accepting, your visit appears within ~30 s; “Event count by event name” lists the events above.

### Browser DevTools (no Google account needed)

- View source on any page: the inline Google tag script contains `gtm.js?id=GTM-M4QHPXQV`.
- On load: exactly one `gtm.js` request (gtag.js is then loaded by GTM’s Google tag); `dataLayer` begins with `consent default` (all denied for a new visitor) → `set ads_data_redaction` → `js` → `{event: 'gtm.js'}`; no `_ga` cookies.
- Click Accept: a `consent update` with `analytics_storage: 'granted'`; `_ga` cookies appear after the next hit.
- Click Decline: `window['ga-disable-G-DEEP3H3Q83'] === true`; no further hits.
- Navigate between pages: no new script requests.

## Privacy

- Matches the published policy (`/privacy#website`): Consent Mode with everything denied until Accept, no analytics cookies before Accept, cookieless pings disclosed, Decline and GPC switch GA4 off, Google signals and ad personalization off, ad consent types always denied, withdrawal from the footer.
- GA4 does not log or store IP addresses ([Google](https://support.google.com/analytics/answer/12017362)). Set GA4 data retention (Admin → Data collection and modification → Data retention) to match the policy.
- If you add other tags to GTM (ads, heatmaps…), update the privacy policy first and respect the same consent state.
